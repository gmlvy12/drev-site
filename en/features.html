Features

100% change detection, before/after evidence, mistake signals, per-project morning briefings, tag search, history and reporting, changes after issue or ordering.

No PDM system? Never miss a change anyway

Built for design teams that live in shared folders — no behavior change required.

🔍

100% change detection (watched formats)

File fingerprints (hashes) catch every change (copies that keep both size and timestamp are caught by the weekly full check), and date-suffixed saves (drawing_240901 → _241001) are automatically recognized as new revisions of the same drawing and compared.

📷

Photos and evidence

Changed spots on drawings are cropped with red boxes (before/after images when the graphics change; old → new value plus the new revision's image when text or values change); BOMs get row-level color diffs with only the changed words highlighted, plus a purchasing-impact summary (added / removed / changed values). Renamed or added columns, moved rows, added sheets, and PDFs whose page numbers shifted are matched correctly too (drawings: PDF and DXF; DWG when a converter is installed).

⚠️

Mistake signals

Content changed but Rev untouched, drawing–BOM spec mismatch, spec conflicts between drawings — suspicious signs are flagged with evidence before they become accidents.

📧

Per-project morning briefing

Every morning at the time you set (7 AM by default — waking the PC from sleep, or, if the time was missed, at the next login (or when the Drev window is opened)), each project gets a briefing as an email draft (sent automatically if an SMTP server is set): "N changes + M to review." Projects with the same recipients are bundled into one email a day (or one per project, if you prefer). A second scan on the same day updates that day's briefing. The owner acknowledges with one click on the watch PC's screen; email recipients reply, and the owner records it — teams that don't track acknowledgements can turn it off. Companies that turn on the optional Forms server can let recipients view and acknowledge changes on the LAN from a link in the email.

🔎

Tag & full-text search

"Where is M-101 used?" — search any equipment tag or text across all drawings and BOMs, then open the file right from the results.

📊

History & reporting

Who acknowledged what and when is kept in your own state.db (before/after images of older revisions for 90 days by default, adjustable in Settings), and the full history exports to Excel for weekly reports and approvals — or as a design change register (Excel) per project and period.

Things people asked for

Same principles throughout: read-only, evidence attached, people make the call.

👤

Who saved it last

Change details and briefings show the last-saved-by name recorded inside the file (DXF, Excel, Word — whatever the CAD or Office app wrote, often the PC user name; empty for PDF and HWPX).

📋

Day-one status report

The baseline scan is not a change, so it used to send nothing. Now day one produces a one-page current state report — several revisions of one drawing number, title-block Rev vs. revision table, drawing–BOM mismatches — with evidence.

📤

Changed after issue

Name your issue (release) folders in Settings; Drev records what was issued and flags when the working original changes afterwards without a newer issued copy — a sign that a subcontractor may hold an old revision.

🧾

Changed after ordering

When a tag or part number on a purchase order changes in the project's drawings or BOM after the order date, the change is marked with the PO and row, and purchasing gets that project's email. Prices are never read or compared.

🔕

Less noise

The first edit of a work-in-progress file with an unchanged Rev is noted, not flagged (once per file until the Rev changes); a further edit without a Rev bump is flagged at once, and so is the file if the Rev is still unchanged 7 days later (configurable). The same tag value conflict between drawings and against the BOM is one card, and five or more files of one type added to one folder fold into one line.

✉️

Recipients and mail presets

Set recipients per project on the project screen. Pick your mail service (Hiworks, Naver Works, Microsoft 365, Gmail) to fill in the server and port. When the sender address is a personal free-mail account (Gmail, Naver, Outlook.com…), drawing images are left out by default.
